## Units and Target-Ledger Denominator

The target ledger, profile {{TARGET_PROFILE}}, version {{TARGET_VERSION}}, declares {{TARGET_TOTAL}} work-level targets. It is canonical for this pipeline, rather than a complete canon for Blake studies. Bibliographies, editions, Archive identifiers, and visual catalogues inform its titles, aliases, categories, expected modalities, and source hints [@bentley1977blakebooks; @bentley1995supplement; @bentley2004records; @butlin1981paintings; @erdman1988complete; @viscomi1993blake].

A local record has a different unit: it is a retained source document or copy-level record. The {{WORKS_PRESENT}} local records must not be read as that many distinct Blake works. Multiple copies and source documents can map to the same ledger target. Image counts likewise have two units: {{TOTAL_IMAGES}} work-image associations reference {{UNIQUE_IMAGE_FILES}} distinct existing local image files, with {{REUSED_IMAGE_ASSOCIATIONS}} associations beyond the unique-file count. Analyses can revisit the same physical image through different records; these associations are not independent image observations. Neither the work-level ledger nor the retained inventory establishes a complete copy-, plate-, impression-, or museum-object census [@viscomi1993blake; @essick1980printmaker; @foxfletcher2018relations].

## Acquisition Architecture and Source Authority

The source registry contains {{SOURCE_REGISTRY_COUNT}} providers: {{SOURCE_PROVIDERS_CSV}}. The William Blake Archive supplies editorial and identifier authority [@blakearchive; @eaves1999standards; @jones2006wba]. Project Gutenberg, Wikisource, Internet Archive, the Erdman edition, museum catalogues, HathiTrust, and scholarly finding lists provide fallback or corroborating leads. They are not interchangeable authorities [@projectgutenberg; @wikisourceblake; @internetarchive; @erdman1988complete; @tateblake; @britishmuseumblake; @hathitrustblake; @essick1969; @mcgann1991textual; @mckenzie1999bibliography].

The acquisition implementation can combine a declared ledger with pinned GitHub TEI inventories and bounded, opportunistic Archive API enrichment. TEI filenames are resolved from the actual inventory before inferred copy-name candidates are tried. Image acquisition normalizes object identifiers and records attempted source URLs. Fallback transcriptions require explicit source, title, attribution, rights, and checksum review. Structured encoding is a model of evidence rather than an assurance that extracted text is Blake-authored reading text [@teiP5; @burnard2014tei; @derose1990text].

These are acquisition capabilities, not activities newly measured by this offline run. Its live Archive metadata status is `{{ARCHIVE_METADATA_STATUS}}`; the saved discovery and source-audit artifacts record reuse or not-rerun states. Previously captured URLs and source commits remain provenance, not fresh endpoint-health evidence. Interface drift and reference rot make this temporal distinction necessary [@reed2014managing; @klein2014reference; @vandesompel2013memento].

## Retained Sources and Independent Analysis Epoch

The retained-source workflow captures source commits, byte sizes, SHA-256 digests, extraction outcomes, and unresolved image references. Publication analysis starts from a new metadata database and copied decoded transcriptions under `{{ANALYSIS_DATA_DIR}}`, while referencing the original image files. The original corpus database, recovery manifest, passage file, and recovery search database are hash-checked before and after analysis. The prior analysis output is preserved separately. This avoids modifying the captured evidence or silently combining new results with stale per-record processing flags.

The saved run identifier is `{{ANALYSIS_RUN_ID}}`. Its analysis producer version is `{{ANALYSIS_PRODUCER_VERSION}}`; its input receipt has SHA-256 `{{ANALYSIS_INPUT_SHA256}}`. The publication software version and the version that actually produced the analysis are separate provenance fields. A package version change does not retrospectively rerun an analysis. Recovery coverage, backup verification, and the corruption-detection restore drill are reported separately in [@sec:supp_recoverability].

## Provenance and Missing-Evidence Queue

Source identifiers, URLs, authority tiers, rights notes, and image links accompany the local records. Coverage joins them to the target ledger and emits missing-evidence candidates for targets that remain partial, missing, or unverified. A candidate guides review; it does not establish that a remote source contains the required evidence. The queue in [@tbl:supp_missing_evidence] is derived from retained coverage and source hints. Endpoint states marked unchecked were not tested during this analysis epoch. Provenance therefore records relationships among source material, acquisition, derived artifacts, and claims without substituting availability for identity or permission [@w3cprov2013overview; @rocrate2022].
